Architecture des données · phase R

Le RAG du POC, du corpus au contexte coach

Le RAG actuel n'est pas une recherche vectorielle plate sur tous les textes d'échecs. Il est composé de deux systèmes complémentaires : OpeningTree connaît la structure déterministe des ouvertures et borne la zone pertinente ; Milvus retrouve la prose pédagogique par similarité sémantique. Le service assemble ensuite les résultats en séparant la position courante, le parent et les suites candidates.

Source

Wikibooks nettoyé, CC BY-SA. Prose uniquement.

Structure

OpeningTree et `eco_code` pour relier la prose à la position.

Vectoriel

Qwen3-Embedding-0.6B, 1024 dimensions, COSINE, HNSW.

Sortie

`RetrievedContext` attribué, puis coach déterministe ou LLM.

Point essentiel. `lichess-org/chess-openings` n'est pas vectorisé. Ses TSV alimentent l'arbre structuré, le matching et la jointure `eco_code`. La prose Wikibooks est la matière indexée dans Milvus. ADR 0006:19-33

A1 · Frontière exacte des données

Avant de suivre les étapes, il faut savoir ce qui entre dans chaque système et ce qui en est volontairement exclu.

Donnée structurée hors Milvus

  • Source : cinq TSV `chess-openings`.
  • Champs : `eco`, `name`, `pgn`.
  • Transformation : coups SAN → UCI, FEN/EPD, parents, enfants, profondeur.
  • Sortie : snapshot `OpeningTree` puis, à terme, collection MongoDB `openings`.
  • Usage runtime : identifier le noeud courant et ses enfants directs.

Pourquoi le pipeline est versionné. Le hash de snapshot inclut le contenu et les métadonnées significatives. Le manifeste Milvus vérifie version de schéma, modèle, dimension, métrique, index et format. Un changement de cleaner, chunking, texte ou métadonnées crée une nouvelle cible ; les anciennes collections ne sont pas supprimées avant validation.

Budget UTF-8

Une section trop longue est découpée en parties ordonnées. Une page trop longue en mode `page` est rejetée, pas tronquée.

Sans overlap

Le chunker ne duplique pas les mots entre chunks. `page_id`, `section_index` et `part_index` permettent de reconstituer.

ID idempotent

Le même `source + text` produit le même ID SHA-256 ; l'ingestion peut vérifier, reprendre et réutiliser.

B2 · Question → intention → RetrievalPlan

Le routeur ne choisit pas librement une collection ni un rayon de recherche. Il produit une intention ; le builder déterministe traduit cette intention en buckets et budgets.

B3 · Recherche Milvus, champ par champ

Pour le plan courant + parent, deux recherches sont exécutées dans la boucle des buckets. Le vecteur est le même ; le filtre et la limite changent.

# current bucket
vector = embed_query(question)
k = 4
filter = opening_node_id == "ruy-lopez-node"
and intent not in ["history", "misc"]
and is_history == false and is_misc == false
search_params = metric COSINE, HNSW ef = max(search_ef, k)
# parent bucket
k = 1
filter = opening_node_id == "before-bb5"
and intent not in ["history", "misc"]

Chemin primaire

Recherche par `opening_node_id` + page/intention. C'est la contrainte la plus précise.

Dégradation contrôlée

Si aucun résultat et qu'un ECO existe, nouvelle recherche bornée par ECO, puis fallback ECO plus large.

Échec visible

Embedding indisponible → `rag_embedding_unavailable`; Milvus indisponible → `rag_store_unavailable`.

B4 · Reranking, déduplication et contexte coach

Le score Milvus n'est pas le score final. `RagService` applique une politique relationnelle avant de transmettre les passages.

  X -- non --> B{"relation"}
  B -- current --> C["score + 0.40"]

  B -- child + current --> CP["score - 0.20"]
  B -- parent --> P["score - 0.25"]

Règles de score actuelles

current+0.40
child + ask_specific_candidate+0.25
child + explain_current_position-0.20
parent-0.25

Les exclusions arrivent avant le ranking : descendant explicitement exclu, noeud hors bucket, history/misc non demandés.

rag.py:204-261

Les constantes ± sont une politique inter-buckets : le bonus est uniforme à l'intérieur d'un bucket et préserve donc son ordre cosine. Une ablation boost vs sans boost reste nécessaire avant de figer ces valeurs.

Conséquence pédagogique. Un chunk `child` conserve `entry_move`. Il peut expliquer une suite possible, mais ne doit pas être reformulé comme un fait de la position courante. Le coach déterministe vérifie également l'URL, la licence et la page source ; sinon il passe en fallback au lieu d'affirmer.
Cible de refactor. Remplacer les constantes par un tri lexicographique explicite : priorité du bucket, puis score cosine décroissant. Cela exprime la politique actuelle sans dépendre d'une magnitude arbitraire ; l'ablation mesurera si cette priorité améliore réellement le contexte coach. ADR 0011
